TRACCIA DELL'ESERCITAZIONE
1. Descrizione del progetto
Una società automobilistica internazionale intende realizzare un'applicazione backend per gestire la propria rete commerciale, 
costituita da diverse Case Madri, concessionari autorizzati e clienti.
L'applicazione dovrà consentire di gestire le informazioni relative alle Case Madri, 
ai concessionari appartenenti alla rete commerciale e ai clienti registrati presso i singoli concessionari.
Ogni Casa Madre può possedere diversi concessionari distribuiti sul territorio nazionale e internazionale.
Ogni concessionario appartiene a una sola Casa Madre e può gestire numerosi clienti.
Ogni cliente deve essere associato a un solo concessionario di riferimento.
Il sistema dovrà permettere di effettuare operazioni di inserimento, modifica, eliminazione e consultazione dei dati, 
oltre a ricerche specifiche che coinvolgano più entità contemporaneamente.








3. Analisi del database
Il database dovrà chiamarsi:

gestione_concessionari

Dovranno essere create tre tabelle principali:
- CASA_MADRE
- CONCESSIONARIO
- CLIENTE

3.1 Tabella CASA_MADRE
La tabella rappresenta le aziende automobilistiche proprietarie delle reti di concessionari.
Campo	Tipo MySQL	Vincoli
id	BIGINT	Primary Key, Auto Increment (Long)
ragione_sociale	VARCHAR(100)	Not Null (String)
sede_legale	VARCHAR(100)	Not Null  (String)
paese	VARCHAR(50)	Not Null (String)
anno_fondazione	INT	 (Integer)
fatturato_annuo	DECIMAL(15,2)	(BigDecimal)

Ogni Casa Madre dovrà avere un identificativo univoco e una ragione sociale.
3.2 Tabella CONCESSIONARIO
La tabella rappresenta i concessionari appartenenti alle Case Madri.
Campo	Tipo MySQL	Vincoli
id	BIGINT	Primary Key, Auto Increment
nome	VARCHAR(100)	Not Null
citta	VARCHAR(100)	Not Null
indirizzo	VARCHAR(150)	
telefono	VARCHAR(20)	
fatturato	DECIMAL(15,2)	
casa_madre_id	BIGINT	Foreign Key

Il campo casa_madre_id dovrà contenere il riferimento alla Casa Madre di appartenenza.
3.3 Tabella CLIENTE
La tabella rappresenta i clienti registrati presso i concessionari.
Campo	Tipo MySQL	Vincoli
id	BIGINT	Primary Key, Auto Increment 
nome	VARCHAR(50)	Not Null
cognome	VARCHAR(50)	Not Null
email	VARCHAR(100)	Unique
telefono	VARCHAR(20)	
data_registrazione	Timestamp default current_timestamp (LocaldateTime)	
concessionario_id	BIGINT	Foreign Key

Il campo concessionario_id dovrà contenere il riferimento al concessionario presso il quale il cliente è registrato.








4. Relazioni tra le entità
Le relazioni da implementare sono le seguenti:

CasaMadre – Concessionario
- Una Casa Madre può avere uno o più concessionari.
- Ogni concessionario deve appartenere a una sola Casa Madre.
- La relazione dovrà essere bidirezionale.
Concessionario – Cliente
- Un concessionario può gestire uno o più clienti.
- Ogni cliente deve essere associato a un solo concessionario.
- La relazione dovrà essere bidirezionale.
Lo studente dovrà utilizzare le annotazioni JPA appropriate per realizzare le relazioni.

Dovrà inoltre individuare il lato proprietario della relazione e il lato inverso, utilizzando correttamente mappedBy.

Dovrà essere prestata particolare attenzione alla serializzazione JSON delle relazioni bidirezionali, evitando problemi di ricorsione infinita.

5. Configurazione del progetto Spring Boot

Configurare il file application.yml per consentire il collegamento al database MySQL.
Configurare inoltre Hibernate affinché possa generare o aggiornare la struttura delle tabelle sulla base delle entità JPA.








6. Prima fase – Implementazione delle entità
Creare le seguenti classi all'interno del package entity:
- CasaMadre
- Concessionario
- Cliente
Per ogni entità dovranno essere rispettati i seguenti requisiti:
1. Utilizzare @Entity.
2. Definire il nome della tabella con @Table.
3. Definire la chiave primaria con @Id.
4. Utilizzare @GeneratedValue.
5. Mappare correttamente tutti gli attributi.
6. Definire le relazioni tra le entità.
7. Utilizzare @Column per specificare eventuali vincoli.
8. Definire opportunamente la strategia di caricamento delle relazioni.
Vincolo: non dovranno essere create tabelle aggiuntive per rappresentare le relazioni, in quanto si tratta di relazioni uno-a-molti e molti-a-uno.
7. Seconda fase – Implementazione dei Repository
Creare tre interfacce Repository:
- CasaMadreRepository
- ConcessionarioRepository
- ClienteRepository
Tutte dovranno estendere JpaRepository, specificando il tipo dell'entità gestita e il tipo della relativa chiave primaria.

I Repository dovranno contenere sia i metodi standard ereditati da JpaRepository sia i metodi personalizzati richiesti nelle fasi successive.













8. Terza fase – Implementazione delle API CRUD
Per ogni entità dovrà essere realizzato un Controller REST e un relativo Service.

I Controller dovranno esporre gli endpoint necessari per effettuare tutte le operazioni CRUD.


8.1 CRUD Casa Madre
Realizzare le seguenti API:
Metodo	Endpoint	Descrizione
POST	/api/case-madri	Inserimento nuova Casa Madre
GET	/api/case-madri	Recupero di tutte le Case Madri
GET	/api/case-madri/{id}	Recupero Casa Madre per ID
PUT	/api/case-madri/{id}	Modifica Casa Madre
DELETE	/api/case-madri/{id}	Eliminazione Casa Madre

Requisiti:
- L'inserimento dovrà verificare che i dati obbligatori siano presenti.
- La modifica dovrà verificare che la Casa Madre esista.
- L'eliminazione dovrà verificare che non siano presenti concessionari associati.
8.2 CRUD Concessionario
Realizzare le seguenti API:
Metodo	Endpoint	Descrizione
POST	/api/concessionari	Inserimento nuovo concessionario
GET	/api/concessionari	Recupero di tutti i concessionari
GET	/api/concessionari/{id}	Recupero concessionario per ID
PUT	/api/concessionari/{id}	Modifica concessionario
DELETE	/api/concessionari/{id}	Eliminazione concessionario

Requisiti:
- Ogni concessionario dovrà essere associato a una Casa Madre esistente.
- In fase di inserimento dovrà essere verificata l'esistenza della Casa Madre indicata.
- In fase di modifica sarà possibile cambiare la Casa Madre di appartenenza.
- L'eliminazione dovrà essere impedita se sono presenti clienti associati.
8.3 CRUD Cliente
Realizzare le seguenti API:
Metodo	Endpoint	Descrizione
POST	/api/clienti	Inserimento nuovo cliente
GET	/api/clienti	Recupero di tutti i clienti
GET	/api/clienti/{id}	Recupero cliente per ID
PUT	/api/clienti/{id}	Modifica cliente
DELETE	/api/clienti/{id}	Eliminazione cliente

Requisiti:
- Ogni cliente dovrà essere associato a un concessionario esistente.
- L'email dovrà essere univoca.
- La data di registrazione dovrà essere valorizzata.
- Dovrà essere possibile modificare il concessionario di riferimento.
- Dovrà essere possibile eliminare un cliente senza eliminare il concessionario associato.

10. Quinta fase – Query personalizzate tramite @Query e JPQL
In questa fase gli studenti dovranno realizzare interrogazioni personalizzate utilizzando l'annotazione @Query.

Le query dovranno essere scritte in JPQL, facendo riferimento alle entità e agli attributi Java.

Non è consentito utilizzare query SQL native tramite nativeQuery = true.
10.1 Query con relazioni tra entità
Esercizio 23 – Clienti per concessionario

Realizzare una query che restituisca tutti i clienti associati a un determinato concessionario.

La ricerca dovrà avvenire attraverso l'identificativo del concessionario.

Esercizio 24 – Concessionari per Casa Madre

Realizzare una query che restituisca tutti i concessionari appartenenti a una determinata Casa Madre.

La ricerca dovrà essere effettuata utilizzando la ragione sociale della Casa Madre.

Esercizio 25 – Clienti per Casa Madre

Realizzare una query che restituisca tutti i clienti appartenenti indirettamente a una determinata Casa Madre.

La ricerca dovrà attraversare la relazione tra Cliente, Concessionario e Casa Madre.

Esercizio 26 – Clienti per città del concessionario

Realizzare una query che restituisca tutti i clienti associati a concessionari situati in una determinata città.

Esercizio 27 – Clienti per paese della Casa Madre

Realizzare una query che restituisca tutti i clienti associati a concessionari appartenenti a Case Madri situate in un determinato paese.
10.2 Query con condizioni multiple
Esercizio 28 – Ricerca dinamica clienti

Realizzare una query che permetta di cercare i clienti attraverso nome e cognome.

Entrambi i parametri dovranno essere opzionali.

Se viene valorizzato solamente il nome, la ricerca dovrà utilizzare solamente il nome.

Se viene valorizzato solamente il cognome, la ricerca dovrà utilizzare solamente il cognome.

Se entrambi i parametri vengono valorizzati, la ricerca dovrà utilizzare entrambe le condizioni.

Esercizio 29 – Ricerca concessionari per città e fatturato

Realizzare una query che recuperi tutti i concessionari appartenenti a una determinata città e aventi un fatturato compreso tra due valori.

Esercizio 30 – Ricerca Case Madri per paese e fatturato

Realizzare una query che recuperi tutte le Case Madri appartenenti a un determinato paese e aventi fatturato annuo superiore a un importo specificato.
10.3 Query con funzioni aggregate
Esercizio 31 – Numero di concessionari per Casa Madre

Realizzare una query che restituisca, per ogni Casa Madre, il numero totale di concessionari associati.

La query dovrà utilizzare:
- COUNT
@Query("""
    SELECT COUNT(c)
    FROM Cliente c
""")
Long countClienti();


- GROUP BY

@Query("""
    SELECT c.citta
    FROM Concessionario c
    GROUP BY c.citta
""")
List<String> findCittaConcessionari();

- LEFT JOIN

@Query("""
    SELECT cl
    FROM Cliente cl
    JOIN cl.concessionario c
    WHERE c.id = :id
""")
List<Cliente> findClientiByConcessionarioId(
    @Param("id") Long id);



Il risultato dovrà includere anche le Case Madri che non possiedono concessionari.

Esercizio 32 – Numero di clienti per concessionario

Realizzare una query che restituisca, per ogni concessionario, il numero totale di clienti associati.

Anche in questo caso dovranno essere inclusi i concessionari che non hanno clienti.

Esercizio 33 – Fatturato complessivo per Casa Madre

Realizzare una query che calcoli il fatturato complessivo generato da tutti i concessionari appartenenti a ciascuna Casa Madre.

La query dovrà utilizzare la funzione SUM.

Esercizio 34 – Fatturato medio dei concessionari

Realizzare una query che calcoli il fatturato medio di tutti i concessionari presenti nel database.

Esercizio 35 – Numero totale di clienti per Casa Madre

Realizzare una query che restituisca per ogni Casa Madre il numero complessivo di clienti registrati presso tutti i suoi concessionari.
10.4 Query con sottoquery
Esercizio 36 – Concessionari sopra la media

Realizzare una query che recuperi tutti i concessionari il cui fatturato è superiore al fatturato medio di tutti i concessionari.

La query dovrà utilizzare una sottoquery con la funzione AVG.

Esercizio 37 – Case Madri con fatturato superiore alla media

Realizzare una query che recuperi tutte le Case Madri aventi un fatturato annuo superiore al fatturato medio delle Case Madri presenti nel database.

Esercizio 38 – Concessionari con almeno un cliente

Realizzare una query che recuperi solamente i concessionari per i quali risulta registrato almeno un cliente.

La query dovrà utilizzare una condizione di esistenza oppure un'opportuna aggregazione.

Esercizio 39 – Case Madri senza concessionari

Realizzare una query che recuperi tutte le Case Madri che non possiedono concessionari associati.

Esercizio 40 – Concessionari con più clienti della media

Realizzare una query che individui i concessionari il cui numero di clienti associati è superiore al numero medio di clienti per concessionario.

La query dovrà utilizzare una sottoquery e un'aggregazione.
